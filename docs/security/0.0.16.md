# Suite 0.0.16 security qualification

This record describes dependency selection and local qualification for planned
suite `0.0.16`, tracked by PMem `task_000474`. It does not confirm publication.
The version manifest and referenced package locks define the implementation
inputs. Native AMD64 qualification and accepted current-main publication remain
release gates.

## Selection and fixes

The upstream audit used official releases and registries on 2026-10-08. Inputs
that were already current stable releases were retained. Compatible npm lock
refreshes cover transitive dependencies as well as direct version pins.

- Go `1.27.2` includes the current Go security fixes. All image-managed Go
  executables, including GitHub CLI, Docker CLI, Compose, gosu, TypeScript and
  tsgolint, use this compiler. The workflow's actionlint build selects the same
  toolchain and reviewed dependency override.
- Node `26.11.1` uses checksum-pinned official archives for AMD64 and ARM64.
  Its matching official Docker tag was unavailable at selection.
- Docker `29.9.0`, Compose `5.6.0`, pnpm `12.10.1`, Redocly `2.60.0`, Vite
  `8.3.4`, Oxlint `1.87.0`, Oxfmt `0.72.0` and Playwright `1.64.0` replace
  their previous releases.
- The Debian snapshot and OCI parent refresh include the `xz-utils` and
  `liblzma5` security update. Exact direct package locks cover both architectures.
- Reviewed overrides fix `x/sys` in actionlint and gosu, `rardecode` in
  gitleaks, `cel-go` in sqlc, KaTeX in Markdown linting, and the CSS selector
  parser bundled with npm. The Vite lock refresh fixes `source-map-js`.
  The npm cache library is updated to compatible `http-cache-semantics` 4.3.0;
  its unresolved advisory scenario is recorded below.
- `x/net` 0.60.0 overrides cover all six affected base tools as well as sqlc
  and goose. gitleaks uses `klauspost/compress` 1.20.1. The current Go
  vulnerability feed exposed fixes absent from the selected Trivy data;
  changing the Go compiler alone did not update these embedded libraries.
- Dockerfile frontend `1.28.0` uses its OCI digest. Buildx is pinned to
  `0.38.0`. upload-artifact `7.0.2` and download-artifact `8.0.2` use their
  exact upstream commits.

[Go's release history](https://go.dev/doc/devel/release#go1.27.2) documents the
Go security fixes. Artifact URLs, checksums, source commits and dependency
versions are recorded in [the manifest](../../manifests/versions.json).

[Go HTTP/2 fixes](https://pkg.go.dev/vuln/GO-2026-6603) require `x/net` 0.60.0.
[The compression advisory](https://pkg.go.dev/vuln/GO-2026-5841) requires
`klauspost/compress` 1.18.7 or newer. The full Go scan checked all 28 Go
executables, including the language tools, compiler tools, frontend native
binaries and PostgreSQL privilege helper.

## Verification

All six images built and passed their native ARM64 smoke checks. Coverage
includes non-root identity and caches, protected Git trust, Go race tests,
sqlc code generation and CEL rule enforcement, Markdown math rendering,
npm selectors and cache wildcard handling, frontend compiler/lint/test tools,
Chromium launch, and PostgreSQL/pgvector initialization and entrypoint behavior.
The archive fixture verifies gitleaks detection, its expected failure status,
and redacted output. Docker/Compose offline checks pass in all five job images.
Live Compose fixtures pass HTTP verification and owned cleanup after success
and intentional failure against Docker Engine 29.4.0 / API 1.54 on ARM64.

Repository static, release, publication, scan-helper and Compose preflight
regressions pass. Dockerfile checks, Bash syntax, ShellCheck, shfmt, actionlint,
Markdown and whitespace checks pass. A cache wildcard regression fails with
4.2.0 and passes with 4.3.0. The sqlc and Markdown fixtures retain compatibility
while exercising their upgraded dependencies.

Official Go, Node and pnpm metadata verifies both architecture hashes, and OCI
pins match the upstream index bytes. ARM64 builds verify downloaded artifacts.
Native AMD64 execution remains pending Actions qualification. Baseline scans
use four published 0.0.15 images and two available local 0.0.15 builds with the
matching baseline manifest; this is not a claim that all six baseline layer
sets were pulled from the registry.

Final image labels and complete scan reports match manifest SHA-256:

Trivy 0.75.0 scans include OS and language packages at every severity, using

## Remaining library findings

- `braces` 3.0.3 remains in Markdown linting and its descendant images.
  [The upstream issue](https://github.com/micromatch/braces/issues/73) and
  [the advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) identify
  CVE-2026-93687 with no patched release. The official registry still selects
  3.0.3. Upgrading the dependent tool does not remove this finding.
- [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) concerns the unmaintained
  `x/crypto/openpgp` packages and has no fixed version. Trivy reports the
  `x/crypto` module in base tools and descendants, including current 0.57.0.
  The binary scans also report this advisory, including goose. Runtime
  reachability and suitable upstream replacements remain unqualified; no
  ignore was added.
- `http-cache-semantics` is upgraded from 4.2.0 to current 4.3.0. A focused
  regression confirms that a mixed `Vary: accept, *` header rejects cache
  reuse; 4.2.0 fails that check. However,
  [CVE-2026-93748](https://github.com/advisories/GHSA-ch52-4w7c-c8xp) remains a
  review concern. Its advisory lists versions through 4.2.0 and no fixed
  release. A controlled test of both official 4.2.0 and 4.3.0 sources still
  permits a shared response with `Set-Cookie` and zero computed maximum age
  to be reused with `Cache-Control: max-stale=3600`. Inspection of npm 12.2.0
  confirms that its `make-fetch-happen` caller explicitly uses `shared: false`;
  it does not select the shared mode used by this reproduction. A manual
  inventory row retains the library observation even when Trivy omits 4.3.0
  from its affected range. The version upgrade is not recorded as proof that
  this advisory is fixed for other callers of the library.

The cache observation can be reproduced with the installed module:

```javascript
const CachePolicy = require('http-cache-semantics');
const request = {
  url: 'https://registry.example/package', method: 'GET', headers: {}
};
const response = {
  status: 200, headers: {
    'cache-control': 'max-age=600', 'set-cookie': 'test=fixture'
  }
};
const policy = new CachePolicy(request, response);
console.log(policy.maxAge()); // 0
console.log(policy.satisfiesWithoutRevalidation({
  ...request, headers: { 'cache-control': 'max-stale=3600' }
})); // true
```
